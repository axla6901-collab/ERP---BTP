Mapping du gabarit → module Flotte

  1. A Sidebar figée. Entrée « Flotte » (option commerciale, masquée si non souscrite) avec 3 sous-liens : Tableau de bord, Véhicules, Échéancier.
  2. B Bandeau figé. Titre + badges (statut technique, alerte échéance). Actions à droite (Affecter, + Entretien), Enregistrer en dernier. Boutons d'écriture visibles seulement pour admin + acheteur.
  3. C Colonne principale (8/12). Fiche = 7 sections : Identification, Caractéristiques/détention, Échéances, Affectation, Entretiens, Sinistres, Documents (GED MinIO).
  4. D Rail contextuel (4/12), collant. Carte mise en avant = prochaine échéance (ambre si < 30 j, rose si dépassée), puis statut, affectation, échéances pastillées, synthèse TCO, historique.

Fil rouge de la flotte : la conformité réglementaire (échéances). Le tableau d'alertes du dashboard et la carte « prochaine échéance » du rail s'appuient sur la même logique J-30 que le module Référencement tiers.

Statut d'une échéance (calcul applicatif)

  • Expiré / ≤ 7 j ligne rose · action requise
  • À renouveler ≤ seuil d'alerte (J-30 par défaut, paramétrable)
  • À jour au-delà du seuil

Aucune vue SQL : statutEcheance(date, seuil, aujourd'hui) en TS pur, testable — calqué sur lib/referencement/conformite.ts.
